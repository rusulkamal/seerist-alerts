Subject Line Formula — Reference

The exact, confirmed rule for every alert subject line in this redesign. One page, nothing else.

The one rule (both cases branch from this)

Single-story and digest subjects aren't two unrelated formats — they're one rule branching on item count. Put the most specific real thing this particular email actually has into the subject; nothing generic, nothing invented.

IF item_count == 1: {Location} · {Headline}
ELSE: {Alert's own name}: {item_count} new updates

Decided: the digest branch stays "alert name + count," with no location added in. The single-story branch adds location because that was the audit's specific complaint (subject wasn't informative); digests don't get the same treatment because cramming multiple countries into one subject line risks the exact clutter this whole redesign is fighting. Alert name already implies location often enough (e.g. "usa: 25+ new updates") that this is an acceptable trade rather than a gap.

Rule 1 — Single-story alert

Used when the email covers exactly one story, one location.

{Location} · {Headline}
  • No content-type label in the subject — ever. Not "Breaking Event ·", not "News ·", nothing. Confirmed earlier in this project.
  • Location is the smallest available unit (city over state over country), matching the internal rule in the Problem statement.
  • Example: Philadelphia, United States · Extreme heat in store for Philadelphia area on Wednesday

Rule 2 — Digest (multiple items or countries)

Used when the email is a batch — a country-level digest, a mixed-content digest, anything with more than one story.

{Alert's own configured name}: {count} new updates
  • The alert's own name is whatever the user named their saved search / subscription — not a generic type label, same rule as the email header.
  • This matches the real pattern already in production — the actual subject line "usa: 25+ new updates" was pulled directly from the inbox, not invented.
  • Real production uses "25+" — an estimate, because the batch isn't fully resolved when the subject line is generated.
  • These mockups use an exact count instead, because the item list is fully resolved (deduplicated, final) before the subject is written. If this ships as-is, expect an exact count; if it ships closer to how production works today, expect an estimate with a "+".

Why two formulas, not one

A single-story alert has exactly one location and one headline to put in the subject. A digest, by definition, doesn't — there's no one location or headline that represents 45 items across 14 countries. Using the same formula for both would mean either cramming an arbitrary single headline into a digest subject (misleading) or dropping location/headline from single-story subjects (losing the clarity that was the whole point). The two formulas are the same rule applied consistently: put the most specific real information the email actually contains into the subject, nothing invented, nothing generic.
